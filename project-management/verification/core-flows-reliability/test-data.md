# Данные тестового пользователя для ручных проверок (#92)

Протокол наполнения тестового пользователя (#91) данными для ручной приёмки редактора, импорта,
замены тегов и учебной сессии. Контекст: PRD `PRD-core-flows-reliability.md`, план — Phase 0,
задача 0.2. Схема, триггеры и RLS-политики этой задачей не менялись (ADR-002), код приложения не
менялся.

Прод и preview делят один проект Supabase, поэтому набор создан один раз и виден на обеих средах.

## Решение о способе

Редактор карточек не сохраняет тип слова и грамматику (замечание P1-001 ревью PRD), поэтому
наполнять набор вручную через него нельзя. Владелец проекта 2026-10-30 разрешил скопировать
**собственные** данные в аккаунт тестового пользователя (правка контракта #92).

Прямой INSERT в SQL editor или через service role не подходит: триггеры
`auto_add_user_id_to_cards` и `auto_add_user_id_to_tags` (`docs/apply-user-isolation-fix.sql`)
выставляют `user_id = auth.uid()`, а без входа пользователя `auth.uid()` пуст, и строка получает
`user_id = NULL`. Поэтому запись выполняется **под тестовым пользователем**: клиент с anon-ключом
входит с его учётными данными, и `auth.uid()`, триггеры и RLS работают штатно. Service role
используется только для чтения данных владельца.

## Что и как создано

| Группа данных                                     | Способ                                                                                                            | Итог                                                                                    |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Карточки (в том числе глаголы-карточки, `other`)  | Копия среза из данных владельца под тестовым пользователем (anon-клиент, вход по паролю)                          | 30 скопированы, `word_type`, `grammar_data`, `base_form`, `learned` перенесены как есть |
| Существительные с артиклем и множественным числом | Тот же срез (выбрано в первую очередь существительных)                                                            | 8 с `article` и `plural` в `grammar_data`                                               |
| Карточки без грамматики (`grammar_data = {}`)     | Две карточки `Testkarte eins` / `Testkarte zwei` вставлены под тестовым пользователем; плюс карточки-глаголы срез | 24 карточки с пустой `grammar_data`, из них 2 без тегов                                 |
| Теги                                              | Копия только тех тегов владельца, что используются выбранными карточками                                          | 7 тегов                                                                                 |
| Связи карточек и тегов                            | Пересоздание `card_tags` по карте старых и новых `id`                                                             | 0 тегов у 2 карточек, 1 у 1 карточки, несколько у 29                                    |
| Глаголы                                           | Копия 5 глаголов владельца под тестовым пользователем с `user_id` = id тестового пользователя                     | 5 глаголов                                                                              |
| Статусы «выучено»                                 | Перенесены вместе со срезом (3 карточки у владельца) и дополнительно выставлены у 2 глаголов                      | 3 карточки, 2 глагола                                                                   |

Для глаголов политика вставки требует явного `user_id` (триггера на `verbs` нет), поэтому
`user_id` задан явно значением id тестового пользователя после входа под ним.

## Итоговый набор

Прочитано под тестовым пользователем 2026-10-30, среда — боевой проект Supabase (общий для прода
и preview), приложение не использовалось, запросы шли через клиент с anon-ключом и сессией
тестового пользователя.

- Карточек: 32 (требуется не менее 10).
- Существительных с артиклем и множественным числом: 8 (не менее 3).
- Карточек без грамматики (`grammar_data = {}`): 24 (не менее 1).
- Тегов: 7 (не менее 3). Карточек без тегов: 2, с одним тегом: 1, с несколькими: 29.
- Глаголов: 5 (не менее 3).
- Выучено: 3 карточки и 2 глагола.
- Проверка владения: чтением через service role подтверждено, что у всех строк `cards`, `tags` и
  `verbs` тестового пользователя `user_id` равен его id (32 / 7 / 5), других владельцев нет.

## Прямой INSERT

Прямой INSERT в SQL editor **не использовался**. Запись через service role без входа под
тестовым пользователем считается недопустимой: триггер при пустом `auth.uid()` записывает
`user_id = NULL`. Допускать этот способ можно только после проверки, что строка получила
корректный `user_id` тестового пользователя.

## Граница безопасности

- Данные владельца читались только на чтение через service role (запрос по `user_id` владельца,
  найденному по адресу в `profiles`), ни одна строка его аккаунта не изменялась.
- Данные других реальных пользователей и демо-пользователя не читались и не изменялись; скрипт
  отказывается работать, если id тестового пользователя совпадает с `DEMO_USER_ID` или с id
  владельца.
- Все записи выполнены под учётной записью тестового пользователя. Скрипт копирования
  одноразовый, локальный, в репозиторий не коммитится; пароли и ключи в репозиторий не попадают.

## Воссоздание набора с нуля

Шаги не зависят от жёстко заданных UUID: идентификаторы определяются по адресам электронной
почты и переменным окружения.

1. В `.env.local` должны быть заданы `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`,
   `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `DEMO_USER_ID` и данные тестового пользователя
   (адрес, пароль, id).
2. Убедиться, что у тестового пользователя нет данных (вход под ним, `cards`, `tags`, `verbs`
   пусты); иначе очистить его данные средствами приложения под ним же.
3. Найти id владельца по его адресу в `profiles` (service role, только чтение). Проверить, что id
   тестового пользователя не совпадает с id владельца и `DEMO_USER_ID`.
4. Прочитать у владельца карточки, теги, связи `card_tags` и глаголы. Выбрать срез: существительные
   с артиклем и множественным числом, карточки с несколькими тегами, одним тегом, выученные.
5. Войти под тестовым пользователем (anon-клиент, пароль). Вставить карточки без `id`,
   `user_id`, `created_at`, `updated_at`: `user_id` проставит триггер. Проверить, что вернувшийся
   `user_id` равен id тестового пользователя.
6. Вставить используемые теги, затем связи `card_tags` по карте старых и новых `id`.
7. Вставить две карточки без грамматики и без тегов (`Testkarte eins`, `Testkarte zwei`).
8. Вставить глаголы владельца с явным `user_id` = id тестового пользователя; у двух из них
   выставить `learned = true`.
9. Прочитать наборы под тестовым пользователем и сверить числа из раздела «Итоговый набор».
