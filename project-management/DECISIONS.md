# Architecture Decisions

Здесь фиксируются решения, которые не стоит передоговаривать заново при каждой следующей задаче.
Одно решение — один раздел. Формат намеренно короткий: что решили, почему, откуда взялось.

Файл читается автоматически вместе с корневым `CLAUDE.md` (он ссылается на него через `@`), так
что всё записанное здесь попадает в контекст каждой сессии — пиши по делу.

## Формат

```markdown
## ADR-NNN — Короткое название решения

Status: `Accepted` | `Superseded by ADR-MMM`

Decision:
Что именно решено, в настоящем времени и конкретно.

Reason:
Почему так, и какая альтернатива отвергнута.

Source: кто/когда/в каком контексте (issue, PR, разговор с датой).
```

## ADR-001 — Автономный цикл Ralph создаёт PR, но никогда не мёрджит

Status: `Accepted`

Decision:
Автономный агент (`.claude/ralph/`) реализует issue и создаёт PR, но мёрдж всегда выполняет
человек, посмотрев Vercel preview этого PR. Агент не имеет доступа к `git commit`/`push`/`gh` —
все мутации git/GitHub делает контроллер детерминированным кодом.

Reason:
`main` автоматически деплоится в прод, автотестов в проекте нет, поэтому единственная реальная
проверка поведения — человек на preview. Автоматический мёрдж убрал бы эту проверку целиком.
Отсутствие git/gh у агента заодно устраняет класс «агент сам себе расширил права».

Source: перенос механизма из `jobflow-cv-pipeline`, 2026-09-17.

## ADR-003 — Сборка не требует серверных секретов Supabase

Status: `Accepted`

Decision:
Сервисный клиент Supabase (Service Role Key) создаётся лениво, при первом обращении —
`getServiceSupabase()` в `src/lib/supabase.ts`. Ни один модуль не создаёт клиент и не проверяет
`SUPABASE_URL`/`SUPABASE_SERVICE_ROLE_KEY` на верхнем уровне. Отсутствие конфигурации — ошибка
конкретного запроса, а не ошибка сборки. В CI эти две переменные намеренно не задаются, чтобы
регресс был заметен сразу.

Ключ Service Role **не** добавляется в окружение Preview на Vercel: preview-URL публичные, а
ключ даёт полный доступ к боевой базе в обход RLS. Preview собирается и открывается; серверные
роуты, которым нужен этот клиент, на preview отвечают ошибкой — это осознанный компромисс.

Reason:
Раньше клиент создавался при вычислении модуля и бросал исключение без переменных. Next собирает
page data для API-роутов на этапе сборки, то есть импортирует этот модуль, — поэтому сборка
требовала боевых секретов, а в Vercel они заданы только для Production. Итог: **каждый**
preview-деплой падал с "Failed to collect page data for /api/cards". Это убивало единственную
реальную проверку поведения перед мёрджем, поскольку автотестов в проекте нет.

Альтернатива «просто добавить ключи в Preview» отвергнута: она чинит симптом ценой раздачи
service-role-доступа публичным preview-URL.

Source: issue #4, найдено при подключении CI, 2026-09-17.

## ADR-002 — Изменения схемы Supabase применяет только человек, и только аддитивно

Status: `Accepted`

Decision:
SQL-схемы и миграции (`docs/**/*.sql`) правит и применяет человек вручную в Supabase SQL editor.
Автономному агенту путь `docs/**` закрыт на уровне permissions, и он обязан ответить
`BLOCKED-DB-CHANGE`. Порядок выкатки изменения данных: аддитивная миграция → код → выкатка →
отдельной задачей удаление старого.

Reason:
Supabase — один и тот же проект для прода и для preview-деплоев, поэтому ломающая миграция роняет
живое приложение немедленно, ещё до мержа связанного PR. Откатить её так же быстро нельзя.

Source: перенос механизма из `jobflow-cv-pipeline`, 2026-09-17.

## ADR-004 — Единственная система стилей — MUI

Status: `Accepted`

Decision:
Tailwind CSS удалён из проекта полностью: пакеты `tailwindcss` и `@tailwindcss/postcss`,
`postcss.config.mjs` и `src/app/globals.css`. MUI (тема в `ThemeProvider.tsx` + `CssBaseline`) —
единственный источник глобальных стилей. Фон страницы, цвет текста и шрифт берутся из темы MUI
(`palette.background.default` = `#f5f5f5`, `palette.text.primary`, стек
`"Roboto", "Helvetica", "Arial", sans-serif`), а не из правил, которые были в `globals.css`.
Полутёмная тема по `prefers-color-scheme`, которая раньше подмешивалась через `globals.css`,
убрана — это было багом (страница темнела вслед за ОС, а компоненты MUI оставались светлыми).
Если понадобится глобальное CSS-правило, ему место в `MuiCssBaseline.styleOverrides` внутри
`ThemeProvider.tsx`, а не в отдельном CSS-файле.

Reason:
В проекте было две системы стилей одновременно, хотя Tailwind нигде не использовался (ни одного
`className` в `src/`) — он остался от шаблона `create-next-app`. Emotion-кеш MUI вставляется в
начало `<head>` (`prepend: true`), поэтому `globals.css` шёл после него и перебивал `CssBaseline`
на `body`, из-за чего фон и шрифт расходились с темой, а в тёмной теме ОС возникала смесь светлых
MUI-компонентов на тёмном фоне.

Отвергнутые альтернативы:
- оставить обе системы и развести конфликт порядка CSS через CSS layers — не решает, что Tailwind
  всё равно не используется, лишь маскирует конфликт;
- перенести правила `body` из `globals.css` в тему 1:1 (`#fff`, Arial) — сохраняет расхождение
  фона/шрифта с уже существующей темой MUI ради «пиксель в пиксель» с прежним (багованным)
  поведением.

Source: issue #5, 2026-09-17.

## ADR-005 — In-memory rate limiting вместо Upstash Redis

Status: `Accepted`

Decision:
Rate limiting на публичных `guest=1` API-эндпоинтах и на `/auth/**` реализован через
in-memory sliding window (`src/lib/rate-limit.ts`) в `src/proxy.ts`, без внешней инфраструктуры.
Лимиты: 60 req/min для guest API, 20 req/5 min для auth. Заголовок `Retry-After` включается в
ответ 429. Реальные вызовы Supabase Auth (signIn/signUp) идут браузер → Supabase напрямую
и покрываются встроенным rate limiting Supabase — дублировать на уровне Next.js нет смысла.

Reason:
Issue #15 рекомендует `@upstash/ratelimit` с Upstash Redis, но эта зависимость требует нового
внешнего сервиса, новых ключей в `.env`, и установки пакета. In-memory подход не требует ничего
нового, совместим с Edge Runtime, и обеспечивает защиту от бёрст-атак в рамках одного
warm-инстанса Edge функции. На Vercel Edge функции живут достаточно долго, чтобы этот подход
был практически значимым.

Отвергнутая альтернатива: `@upstash/ratelimit` — подходит как апгрейд, если в будущем
понадобится точный глобальный лимит (тогда нужны `UPSTASH_REDIS_REST_URL` и
`UPSTASH_REDIS_REST_TOKEN` в `.env.example`).

Source: issue #15, 2026-09-18.
